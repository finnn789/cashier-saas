### V6 migration `src/main/resources/db/migration/V6__order_status_open_completed_cancelled.sql`
1. `ALTER TABLE sales_orders DROP CONSTRAINT sales_orders_status_check;`
2. `UPDATE sales_orders SET status = 'COMPLETED' WHERE status IN ('NEW','CONFIRMED','PREPARING','READY') AND payment_status = 'PAID';`
3. `UPDATE sales_orders SET status = 'OPEN' WHERE status IN ('NEW','CONFIRMED','PREPARING','READY') AND payment_status = 'UNPAID';`
4. Any remaining row with an old status (e.g. payment_status `REFUNDED`) must make the migration FAIL loudly rather than be silently mapped: add a `DO $$ ... RAISE EXCEPTION ... $$` guard that counts rows whose status is not in ('OPEN','COMPLETED','CANCELLED').
5. `ALTER TABLE sales_orders ADD CONSTRAINT sales_orders_status_check CHECK (status IN ('OPEN','COMPLETED','CANCELLED'));`

### Server-side hold bill: replace items of an OPEN POS order
- Route: `PUT /api/v1/cashier/outlets/{outletId}/fnb/orders/{orderId}/items` in `FnbStaffOrderController` (same `/cashier/**` security = OWNERMERCHANT + CASHIER). Body: the existing `FnbPosOrderRequest` (`serviceType`, `customerLabel`, `items`), `@Valid`. Returns `ApiResponse.success("Item pesanan diperbarui.", FnbStaffOrderResponse)`. No `Idempotency-Key` (full replacement is idempotent).
- Service: `FnbPosOrderService.replaceItems(TenantPrincipal principal, UUID outletId, UUID orderId, FnbPosOrderRequest request)`, `@Transactional`, in this order: `guard.requireOutlet`; `orders.lockTenant(tenantId)`; re-check context exactly like `checkout` (inactive tenant/fnb/outlet -> 404); load the order with `orders.byId(tenantId, outletId, orderId)` + `orders.refreshOrder(order)`, missing -> `ResourceNotFoundException` (404, no cross-tenant evidence); `source != POS` -> `OperationConflictException("Hanya pesanan POS yang dapat diubah.")`; pending gateway attempt (`FnbGatewayAttemptRepository.pendingForOrder`) -> 409 "Gateway attempt masih tertunda."; existing discount (`FnbDiscountRepository.byOrder`) -> 409 "Pesanan sudah memiliki diskon; item tidak dapat diubah."; service-type validation shared with `checkout` (same private method, not a copy); price with `FnbOrderPricingService.price(...)` using the ORDER'S snapshot rates (`getTaxRateSnapshot()`, `getServiceChargeRateSnapshot()`), through ONE private method that both `checkout` and `replaceItems` call to build the `LineInput` list (no duplicated mapping); remove old lines with a new `FnbOrderRepository.deleteLines(UUID tenantId, UUID outletId, SalesOrderEntity order)` that reuses `items(...)`/`itemOptions(...)` and removes options before items; entity method `replaceLines(ServiceType serviceType, String customerLabel, Charges charges)` (calls `requireOpenUnpaid()`, requires `discountAmount` zero, requires `serviceType != null`, sets serviceType, customerLabel (trimmed by the caller like checkout), subtotal, taxAmount, serviceChargeAmount, total = subtotal + tax + service charge); `persistLines(...)` (existing private method); `orders.flush()`; audit `AuditLogEntity.recordAction(..., Action.FNB_ORDER_ITEMS_REPLACED, order.getId(), null, "subtotal=<old>-><new>")` with a NEW enum constant `FNB_ORDER_ITEMS_REPLACED("SALES_ORDER")` (check first that `audit_logs.action` has no CHECK constraint in V1..V5; if it has one, stop and report); return `response(order)`.
- `requestFingerprint` and `idempotencyKey` of the order are NOT changed (a retried checkout with the original key after a replace returns 409 if the payload differs, or the CURRENT order if it matches; report which one the existing `replay` gives).
- Cancel a held bill = existing `POST .../{orderId}/cancel` with reason (audit already exists). Pay = existing payments route. List held bills = existing `GET .../fnb/orders?status=OPEN&paymentStatus=UNPAID`.
