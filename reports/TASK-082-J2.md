# TASK-082 J2 report: REST gating

Not compiled or tested (policy: no Maven). Java root `src/main/java/org/lite/project/cashiersaas/`.

## Changed files
`service/CashierInvitationService.java`, `service/MerchantStaffService.java`, `service/FnbRefundService.java`, `service/MerchantAuditService.java`, `service/FnbSalesReportService.java`, `service/DailySummaryService.java`, `repository/DailySummaryDispatchRepository.java`. No other file touched. Each service got one new injected field `PlanEntitlementService planEntitlementService` (Lombok constructor).

## Contract points
- `planEntitlementService.require(tenantId, PlanCode.PRO)` placed right after `guard.requireOwner(...)` (so another tenant never sees a 402 before the ownership/404 check) and before any side effect, in: `CashierInvitationService.issue`; `MerchantStaffService.list/deactivate/reactivate/resetPassword`; `FnbRefundService.refund`; `MerchantAuditService.list`; `FnbSalesReportService.csv`.
- Refund idempotent replay: the check is before the replay lookup, so a downgraded tenant gets 402 even when it retries an earlier Idempotency-Key. Note `orders.lockTenant` still runs first (existing order, tenant id from the principal), so the 402 is thrown while the tenant lock is held until rollback; harmless.
- Invitation claim: `subscriptionRepository.findActiveAt(...).isEmpty()` (J1's A1 caller) was replaced by `planEntitlementService.effectivePlan(tenantId, now).compareTo(PlanCode.PRO) < 0` in the second condition chain, so a downgraded tenant gives the same `ResourceNotFoundException("Undangan tidak ditemukan atau tidak dapat digunakan.")`. Effective plan FREETIER also covers "no active row" (effectivePlan defaults to FREETIER), so the old check is subsumed. The `SubscriptionRepository` field and import were removed from this service (J1 had added the `findActiveAt` call; no other use).
- Idempotent re-claim branch unchanged (it sits before the plan check): it only re-publishes member sync and returns the claim response; it grants no access (cashier access is computed in `MerchantAccessRepository`, which requires PRO), so a downgraded already-claimed cashier gets nothing new. Re-publish of `ACTIVE` sync for such a cashier is left as is.
- Free sales report (`report` only): `query(...)` validation runs first (400s keep priority), then `effectivePlan == FREETIER` => `startDate < LocalDate.now(outletZone) - 29 days` throws `PlanUpgradeRequiredException(PlanCode.PRO)` (402). For FREETIER `hourly`, `cashiers`, `shifts` are `List.of()` and their three queries are skipped; summary, transactions, top products, payment breakdown stay. Done with a `boolean full` parameter on the private `assemble`; `summarize` (internal/AI callers) passes `true` and has no plan check; `csv` requires PRO so it needs no window check. PRO/PREMIUM and a running trial: full report, no window.
- Daily summary: `onShiftClosed` returns when `effectivePlan(tenantId, now) != PREMIUM` (one entitlement check, placed after the open-shift check). `activeFnbOutlets(Instant now)` now filters in JPQL with `EXISTS` on an active PREMIUM `SubscriptionEntity` row OR `tenant.premiumTrialStartedAt > now - TenantEntity.PREMIUM_TRIAL_DURATION` (private static `premium(tenantPath)` string builder inside the repository, shared by both queries). Retry rows for a tenant that has since downgraded are skipped too: `retryable(...)` gained a trailing `Instant now` parameter and the same predicate on `d.tenant` (no N+1, same query).

## Deviations
- Signature changes: `DailySummaryDispatchRepository.activeFnbOutlets()` -> `activeFnbOutlets(Instant now)`; `retryable(int, Instant, LocalDate, int)` -> `retryable(int, Instant, LocalDate, int, Instant now)`. Only `DailySummaryService.runFallback` calls them.
- `PlanEntitlementService.require` uses `Instant.now()` (J1 contract); `DailySummaryService` and the report use `Instant.now()` for `effectivePlan` rather than the `now` of `runFallback(Instant)` in `onShiftClosed` (no clock there); the sweep paths use the passed `now` through the repository query.

## Open questions / risks
- The PREMIUM JPQL (`s.tenant = o.tenant`, `s.startsAt <= :now`, literal `'PREMIUM'`/`'ACTIVE'`) is uncompiled; `PlanCode`/`StatusConstants.ACTIVE` are written as string literals like the existing queries. If Hibernate rejects the entity-equality in the subquery use `s.tenant.id = o.tenant.id`.
- The Free report window uses `query.startDate` (the requested, defaulted start); a Free tenant requesting exactly today-29 is allowed (30 days inclusive).
- An expired trial plus an expired paid row: `effectivePlan` FREETIER; both PREMIUM predicates agree with `PlanEntitlementService` (trial strictly within 14 days, paid row `endsAt` exclusive).
