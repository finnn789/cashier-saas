## Assumptions about behaviour / status codes
- Pay and open return 200 or 201 (helpers accept both, like existing tests); refund, close, force close, current, list, detail return 200; duplicate open / double close / second refund / missing shift return 409; invalid key, blank/oversized reason, invalid cash amounts return 400; cashier on `/merchant/**` returns 403; anonymous 401; foreign tenant or outlet 404.
- Sales report with zero qualifying rows returns `summary.transactionCount = 0` (not null).
- `totalsByMethod` order is by method name (CASH before MANUAL_NON_CASH), as in the repository `order by p.method`.
- JSON money fields are read through `BigDecimal(String.valueOf(jsonPathValue))` and compared with `compareTo`.
- `app.payment.mock-gateway.enabled=true` in the test profile (set in TASK-076 W5) so the gateway test runs.
- The 409 raised after `order.markRefunded()` / `attempt.resolve(...)` relies on the transaction rolling back (asserted through the integration tests).
